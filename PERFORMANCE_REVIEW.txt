--- 1. Batch Rust FFI: getAllNeighbors  (estimated ~0.5s saved) ----------------

Files changed:
  - hnsw-native/src/hnsw.rs        → added get_all_neighbors() method
  - hnsw-native/src/lib.rs         → added hnsw_get_all_neighbors C export
  - src/hnsw/hnswNative.mts        → added getAllNeighbors() TS binding + buffer
  - src/hnsw/hnswGraphStorage.mts  → updateNodeNeighbors uses getAllNeighbors
  - src/hnsw/hnswIndex.mts         → buildNeighborList uses getAllNeighbors

What: Previously, every dirty-node update called getNeighbors() once per layer
(up to 4 FFI calls per node). With ~900K dirty-node updates per benchmark run,
that was ~2.4M FFI round-trips through koffi.

The new get_all_neighbors() Rust function returns ALL layers in a single call:
  [nodeLevel, count0, nb0_docIds..., count1, nb1_docIds..., ...]

This reduces FFI calls from ~2.4M to ~0.6M (4× fewer boundary crossings).

--- 2. Page cache: {raw, usable} pairs  (44.0s → 37.2s) ----------------------

Files changed:
  - src/hnsw/hnswGraphStorage.mts  → _pageCache stores {raw, usable} objects

What: The _pageCache previously stored raw Buffer blocks (4096 bytes). Every
call to updateNodeNeighbors had to call raw.subarray(1) to get the usable
slice — that's ~900K subarray() allocations per run, each creating a new
Buffer view object.

Now _pageCache stores {raw: Buffer, usable: Buffer} pairs. The usable slice
is computed once when the page enters the cache and reused for all subsequent
accesses. This eliminates ~900K Buffer view allocations.

readPage() and writePage() updated to maintain the pair invariant.

--- 3. MockFile bulk truncate + sector pooling  (37.2s → 34.1s) ---------------

Files changed:
  - src/core/mockfile.mts  → truncate(), writev(), constructor

What: CPU profiling showed MockFile.truncate() at 7.0% of total time. It was
allocating one Buffer.alloc(sectorSize) per sector when growing the file —
the log file truncate/grow cycle caused thousands of individual allocations.

Three optimizations:
  a) Bulk allocation: when growing by N sectors, allocate one Buffer of
     N × sectorSize and use subarray() to create sector views (1 alloc vs N).
  b) Sector pooling: when truncating down (log cleanup), freed sectors go into
     a pool. When growing again, pooled sectors are reused (zero-filled).
  c) writev() fast path: skip Buffer.concat() for single-buffer calls (common
     case for block writes).

--- 4. MockFile writev fast path for aligned writes  (34.1s → 32.9s) ----------

Files changed:
  - src/core/mockfile.mts  → writev()

What: For sector-aligned writes spanning whole sectors (the common case for
FreeBlockFile block writes), we now do a single Buffer.from() copy of the
entire data, then subarray into per-sector views. This replaces N separate
Buffer.from() copies in write_sector() (one per sector), reducing allocation
count by ~16× for 4096-byte blocks with 256-byte sectors.

--- 5. FBF readBlock: allocUnsafe  (part of 34.1s → 32.9s) --------------------

Files changed:
  - src/freeblockfile/io.mts  → readBlock()

What: readBlock() used Buffer.alloc() which zero-fills the buffer before
reading from disk. Since file.read() immediately overwrites all bytes, the
zero-fill is wasted work. Changed to Buffer.allocUnsafe() which skips the
zero-fill. Saves ~0.15s for the benchmark's disk read patterns.

--- 6. Direct byte writes in updateNodeNeighbors  (32.9s → 32.0s) -------------

Files changed:
  - src/hnsw/hnswGraphStorage.mts  → updateNodeNeighbors, _updateNodeNeighborsFromDisk

What: Replaced Buffer.writeUInt32LE() / writeUInt16LE() / writeUInt8() calls
with direct byte indexing (usable[o] = pg, usable[o+1] = pg >> 8, etc.).

Buffer's write methods include bounds checking, type coercion, and function
call overhead. Direct byte indexing compiles to simple array stores in V8's
JIT. With ~900K dirty-node updates × ~16 neighbors each, this eliminated
millions of function calls. writeUInt32LE and writeUInt16LE vanished from
the CPU profile hotspots.

================================================================================
  PRIOR SESSION OPTIMIZATIONS (83.8s → 44.0s, for context)
================================================================================

These were done in a previous session and are already in the codebase:

  1. HNSW 6-byte neighbor format (reduced node size, better cache locality)
  2. B+tree deferred flush (batch serialize at commit time, not per mutation)
  3. RecordStore zero-copy writes
  4. Per-node _rawBuffer caching in B+tree (reuse buffer across commits)
  5. VectorHeapFile page cache (avoid re-reading embedding pages)
  6. updateNodeNeighbors sync-or-Promise pattern (avoid microtask overhead)
  7. Raw-block cache in HNSWGraphStorage (zero-allocation stale page promotion)
